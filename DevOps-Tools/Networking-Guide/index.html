    Networking¶

    Introduction to Computer Networking¶

    What is Networking?¶

    Networking is the process of connecting two or more devices to exchange data and share resources using communication protocols.

    Why Networking Matters in DevOps¶

    • Enables communication between tools, services, and users
    • Critical for CI/CD, monitoring, logging, and automation
    • Ensures security, performance, scalability, and reliability
    • Provides the foundation for cloud, containers, and microservices

    Client ↔ Server Architecture¶

    • Client (user/device) sends a request
    • Server processes the request
    • Server sends back the response

    LAN, WAN & Internet¶

    • LAN (Local Area Network): Connects devices in a small area like home, office, or campus
    • WAN (Wide Area Network): Connects LANs over large distances like cities or countries
    • Internet: Global network of networks that connects the world

    Real-World Request Flow¶

    1. User enters a URL in the browser.
    2. Browser sends the request to DNS.
    3. DNS resolves the domain to an IP address.
    4. Request travels over the internet.
    5. Load balancer distributes the traffic.
    6. Application processes the request.
    7. Database returns the data.
    8. Response is sent back to the user.

    Where Networking is Used in DevOps¶

    • Cloud infrastructure
    • Containers and Docker
    • Kubernetes services
    • CI/CD pipelines
    • Monitoring and logging
    • Security and firewall rules
    • Microservices communication

    OSI & TCP/IP Models¶

    OSI Model¶

    The OSI model defines how data travels from one device to another in seven layers.

    1. Physical – Transmission of raw bits over physical media.
    2. Data Link – Frame delivery on the same network.
    3. Network – Routing packets between networks.
    4. Transport – End-to-end communication and reliability.
    5. Session – Establishing and maintaining connections.
    6. Presentation – Data translation and encryption.
    7. Application – User-facing network services.

    TCP/IP Model¶

    The TCP/IP model is used for internet communication.

    • Network Interface – Hardware and drivers.
    • Internet – IP addressing and routing.
    • Transport – TCP/UDP communication.
    • Application – Protocols like HTTP, DNS, SSH.

    IP Addressing & Subnets¶

    IP Addressing¶

    • IPv4 uses 32-bit addresses like 192.168.1.10.
    • IPv6 uses 128-bit addresses like 2001:0db8::1.
    • Every device on a network needs a unique IP address.

    Subnets and CIDR¶

    • Subnets divide a large network into smaller segments.
    • CIDR notation like 192.168.1.0/24 defines network and host bits.
    • Smaller subnets help isolate traffic and improve performance.

    Common Ports¶

    • 22: SSH
    • 80: HTTP
    • 443: HTTPS
    • 53: DNS
    • 3306: MySQL
    • 5432: PostgreSQL

    DNS and Load Balancing¶

    • DNS resolves domain names to IP addresses.
    • Load balancers distribute traffic across multiple servers.
    • In cloud-native environments, DNS and load balancing are essential for resilient applications.

    Key Networking Concepts for DevOps¶

    Network Protocols¶

    • TCP/IP: Foundation for internet communication
    • HTTP / HTTPS: Protocols for web traffic
    • DNS: Resolves domain names to IP addresses
    • Load balancing: Distributes traffic across servers

    Common Networking Devices¶

    • Hub: Multi-port repeater that broadcasts data to all connected devices.
    • Switch: Connects devices in a LAN and sends data only to the intended device using MAC addresses.
    • Router: Connects multiple networks (LAN to WAN) and routes data based on IP addresses.
    • Gateway: Acts as an entry/exit point between different networks or protocols.
    • Modem: Converts digital signals to analog and back to connect to an ISP over telephone, cable, or fiber.
    • Firewall: Monitors and controls incoming and outgoing network traffic with security rules.

    Network Device Comparison¶

    Device OSI Layer Main Function Works On Example Use Key Point
    Hub Layer 1 Broadcasts data to all ports Bits Legacy lab environments No intelligence, causes collisions
    Switch Layer 2 Forwards data to specific device Frames Office LAN Uses MAC address table
    Router Layer 3 Routes data between networks Packets Connects LAN to Internet Uses IP address and routing table
    Gateway Layer 4-7 Protocol translation Data/Packets API gateway in apps Different protocols can communicate
    Modem Layer 1 Converts digital ↔ analog Bits ISP connection Provides internet access
    Firewall Layer 3-7 Filters and controls traffic Packets/Data Protects servers and network Allows or blocks based on rules

    Network Device Rule¶

    Remember the basic rule:

    Hub (Dumb) < Switch (Smart) < Router (Smarter) < Firewall (Smartest & Secure)

    Devices work together to deliver the right data to the right place securely and efficiently.

    Networking Tips for DevOps¶

    • Use strong firewall rules and least-privilege access.
    • Understand how DNS, IP addressing, and routing affect deployments.
    • Always validate network paths for application traffic.
    • Know common protocols like TCP, UDP, HTTP, HTTPS, and DNS.

    Interview Tips¶

    • Networking is one of the most frequently tested topics in DevOps interviews.
    • Focus on how networking supports applications, security, and scalability.

    Remember¶

    Every application request depends on networking before reaching the server.
